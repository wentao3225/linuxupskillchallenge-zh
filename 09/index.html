    第 9 天 - 深入网络

    • 教学视频：Lesson video（英文）
    • 补充视频：Networking（英文）

    引言

    你的服务器现在运行着两个服务：负责远程登录的 sshd 和负责 web 访问的 apache2。它们都通过 TCP/IP 的“端口”向整个世界开放——分别是 22 和 80。

    作为系统管理员，你需要弄清楚自己的服务器上开放了哪些端口，因为每一个开放的端口同时也是潜在的攻击靶点。你还得能够部署相应的监控与管控措施。

    今日任务

    • 用防火墙保护你的 web 服务器

    操作步骤

    首先来看两种查看服务器上开放端口的方法：

    • ss——“socket status”（套接字状态）的缩写，是一个标准工具，用来取代老旧的 netstat
    • nmap——这款“端口扫描器”默认通常不会安装

    ss 可用的选项非常丰富，先试试这个：ss -ltpn

    输出的每一行显示了哪些端口在哪些接口上开放：

    sudo ss -ltp
State   Recv-Q  Send-Q   Local Address:Port     Peer Address:Port  Process
LISTEN  0       4096     127.0.0.53%lo:53        0.0.0.0:*      users:(("systemd-resolve",pid=364,fd=13))
LISTEN  0       128            0.0.0.0:22           0.0.0.0:*      users:(("sshd",pid=625,fd=3))
LISTEN  0       128               [::]:22              [::]:*      users:(("sshd",pid=625,fd=4))
LISTEN  0       511                  *:80                *:*      users:(("apache2",pid=106630,fd=4),("apache2",pid=106629,fd=4),("apache2",pid=106627,fd=4))

    这些网络记法可能有点让人犯晕，但上面几行的意思是：端口 80 和 22 在所有本地 IP 地址上“向全世界”开放，而端口 53（DNS）只在一个特殊的本地地址上开放。

    接下来用 apt install 安装 nmap。它的工作方式相当不同：主动探测 1000 个甚至更多的端口，逐一检查是否开放。它最出名的用途是扫描别人的远程机器——请别这么做——不过用它来扫描自己的服务器、核对自己的配置，非常顺手：

    $ nmap localhost

Starting Nmap 5.21 ( http://nmap.org ) at 2013-03-17 02:18 UTC
Nmap scan report for localhost (127.0.0.1)
Host is up (0.00042s latency).
Not shown: 998 closed ports
PORT   STATE SERVICE
22/tcp open  ssh
80/tcp open  http

Nmap done: 1 IP address (1 host up) scanned in 0.08 seconds

    端口 22 提供的是 ssh 服务——你现在就是通过它连上来的——所以它是开放的。如果 Apache 正在运行，端口 80/http 也会开放。每开放一个端口，“攻击面”就扩大一分，所以最佳实践是：用不到的服务就关掉。

    还要注意，“localhost”（127.0.0.1）是回环（loopback）网络设备。只“绑定”到这个地址的服务，仅本机可用。想看清真正暴露给外界的部分，先用 ip a 命令找到你实际网卡的 IP 地址，然后再对它 nmap 一把。

    主机防火墙

    Linux 内核内置了名为 “netfilter” 的防火墙功能。我们通过各种工具来配置和查询它，其中最底层的是 iptables 命令，以及更新的 nftables。它们强大但也复杂，所以我们改用一个更友好的替代品——ufw，即 “uncomplicated firewall”（简单防火墙）。

    先输入 sudo iptables -L，列出当前生效的规则：

    你会看到类似这样的输出：

    Chain INPUT (policy ACCEPT)
target  prot opt source             destination

Chain FORWARD (policy ACCEPT)
target  prot opt source             destination

Chain OUTPUT (policy ACCEPT)
target  prot opt source             destination

    也就是说，基本上等于没有防火墙——任何流量都可以去往任何地方。

    ufw 用起来非常简单。8.04 LTS（长期支持版）之后的 Ubuntu 安装都默认自带它，如果需要安装：

    sudo apt install ufw

    然后，要允许 SSH、拒绝 HTTP，就输入：

    sudo ufw allow ssh
sudo ufw deny http

    当心！ 别忘了显式 ALLOW ssh，否则你会和服务器彻底失联！如果不明确允许，防火墙会默认拒绝该端口。

    接着用下面的命令启用它：

    sudo ufw enable

    现在再输入 sudo iptables -L，会列出由此生成的详细规则——其中应该有这样一条：

    “DROP       tcp  --  anywhere             anywhere             tcp dpt:http”

    这样做的效果是：虽然你的服务器仍在运行 Apache，但从“外面”已经无法访问了——所有目标端口为 http/80 的入站流量都被 DROP 掉了。自己动手验证一下吧！之后你多半想把它恢复回来：

    sudo ufw allow http
sudo ufw enable

    实际运用中，只要确保没有运行多余的服务，往往就足够安全，基于主机的防火墙并非必需——不过这在很大程度上取决于你配置的是什么类型的服务器。无论如何，希望这一课让你对这些概念有了些感觉。

    顺带一提：这台用来测试/学习的服务器，现在应该把 http/80 重新放开，因为那些 access.log 日志文件会让你真切体会到，在一个充满敌意的世界里运营一台服务器是什么滋味。

    使用非标准端口

    偶尔，把某个服务重新配置到非标准端口上提供也是合理的——对 ssh/22 尤其常见这类建议——具体做法是修改 /etc/ssh/sshd_config 中的配置。

    有人把这称为“隐匿式安全”（security by obscurity）——好比把大门的锁眼挪到一个不寻常的位置，而不是改进锁本身；或者给坦克涂上迷彩，而不是加厚装甲——但它*确实*能有效消灭机会主义黑客的攻击，而对大多数服务器来说，这才是主要威胁。

    不过，如果你真打算这么做，请记住你已经配置好的所有规则和安全工具。例如你在用 AWS，并把 SSH 端口改成了 2222，那还需要在该实例的 EC2 安全组里放行这个端口。

    本课命令速查（中文版新增）

    命令 用途
    ss -ltpn 查看监听端口与对应进程（取代旧的 netstat）
    apt install nmap 安装端口扫描器 nmap
    nmap localhost / nmap 网卡IP 扫描本机 / 指定地址的开放端口
    ip a 查看网卡 IP 地址
    sudo iptables -L 列出当前生效的防火墙规则
    sudo apt install ufw 安装 ufw 防火墙
    sudo ufw allow ssh / sudo ufw deny http 放行 / 拒绝某服务或端口
    sudo ufw enable 启用防火墙
    sudo ufw allow http 重新放行 http/80
