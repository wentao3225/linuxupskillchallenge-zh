# 第 17 天 - 从源码构建

* 教学视频：[Lesson video](https://youtu.be/a9_hry-8Hhw)（英文）
* 补充视频：[Install and config from the source](https://www.youtube.com/live/5oGwnrd44BI?t=8126s)（英文）

## 引言

几天前我们看过，当需要不常见的应用——或者比标准软件仓库里更新的版本——时，可以让 `apt-cache` 去搜索额外的软件仓库。

今天我们要更进一步——字面意义上的“追根溯源”。这不是可以轻率从事的事——软件包管理器存在的全部意义就是让你省心——但偶尔这么做确实有正当理由，而且你应当了解它、对它心里有数。

到目前为止，我们安装的应用都来自软件仓库。那里的文件是“二进制包”（binaries）——预先编译好，而且常常由你的发行版做过定制。可能不那么显眼的一点是：你的发行版是从一批彼此独立、互不协调的开发项目（也就是“上游”（upstream））拿到这些应用的，而这些开发者一直在开发新版本。今天我们就去其中一个项目，下载源码，编译并安装它。

（`apt` 这类软件包管理器做的另一件大事，是识别并安装所需的“依赖”（dependencies）。在 Linux 世界里，许多开源应用都这样复用现成的基础设施，但要手动解决依赖可能相当麻烦。不过，我们今天从源码安装的这个应用相当少见——它是完全独立、不依赖别的东西的。）

## 今日任务

* 下载一份源码 tarball
* 解开源码并完成构建

## 先备齐必需的工具

项目通常以“源文件”的形式发布应用，用 C、C++ 或其他编程语言写成。我们要拉下来的就是这样的源文件，但只有把它编译成“可执行文件”——一个我们的服务器能运行的程序——它才对我们有用。所以，先要装上一套常见编译器等工具的标准组合。在 Ubuntu 上，这套工具的软件包叫 “build-essential”。像这样安装：

`sudo apt install build-essential`

## 获取源码

先确认你已经装了 `nmap`，输入 `nmap -V` 看看是什么版本——这是从标准软件仓库装来的那个版本。接着输入 `which nmap`，看看这个可执行文件存放在哪里。

现在我们去开发者的“项目主页” _http://nmap.org/_，抓一个最新的前沿版本。找到下载页面，再找到 “Source Code Distribution” 一节，以及 “Latest development nmap release tarball” 这个链接，记下它的 URL——类似这样：

     https://nmap.org/dist/nmap-7.70.tar.bz2

这是 7.70 版——编写这份讲义时的最新开发版，现在可能已经变了。接下来把它拉到你的服务器上。第一个问题是放在哪里——我们放到你的主目录里，先用这条命令回到主目录：

`cd`

然后用 `wget`（“web get”）直接下载文件：

`wget -v https://nmap.org/dist/nmap-7.70.tar.bz2`

`-v`（verbose）会给出一些反馈，让你能看到发生了什么。下载完成后，列出目录内容检查一下：

`ls -ltr`

正如我们学过的，文件名的结尾通常是文件格式的线索——这里的 “.bz2” 表示它是一个用 bz2 算法压缩的 tarball。虽然可以分两步先解压、再解开文件组合，但一条命令就能搞定——像这样：

`tar -j -x -v -f   nmap-7.70.tar.bz2`

……其中 `-j` 表示“先解压 bz2 文件”，`-x` 是解开（extract），`-v` 是显示过程（verbose），`-f` 则表示“文件名跟在后面”。实际操作中我们通常更简明地写成：

`tar -jxvf  nmap-7.70.tar.bz2`

那么，来看看结果：

`ls -ltr`

记住列表里目录的开头是 “d”，你会看到多出了一个目录：

     -rw-r--r--  1 steve  steve  21633731    2011-10-01 06:46 nmap-7.70.tar.bz2
     drwxr-xr-x 20 steve  steve  4096        2011-10-01 06:06 nmap-7.70

现在用 `mc` 去探索里面的内容，或者干脆 `cd nmap-7.70`——你应该能用 `ls` 和 `less` 找到并阅读真正的源代码。哪怕完全不懂编程，里面的注释读起来也颇有乐趣。

按照惯例，源码的根目录里通常会有一批全大写文件名的文本文件，比如 README 和 INSTALLATION。找到它们，用 `more` 或 `less` 读一读。很重要的一点是：“上游”项目的程序员并不是专为 Ubuntu、CentOS——甚至不是为 Linux——写的。他们用 C 或 C++ 等语言写出了一个正确可用的程序并发布出来，但如何针对我们的操作系统、芯片类型等把它编译出来，得靠我们自己弄清楚。（这多少能让你体会到 CentOS、Ubuntu 这类发行版以及 `apt`、`yum` 这类工具带来的价值，也就能想象自己从零搞一套 Linux From Scratch 有多难。）

在本例中，我们会看到一个 INSTALL 文件，里面是类似这样的简短说明：

     Ideally, you should be able to just type:

     ./configure
     make
     make install

     For far more in-depth compilation, installation, and removal notes
     read the Nmap Install Guide at http://nmap.org/install/ .

实际上，这对许多软件包来说都是相当标准的流程。每一步的作用如下：

* `./configure` ——一个脚本，用来检查你的服务器（比如是 ARM 还是 Intel 架构、32 位还是 64 位、装的是什么编译器等）。它还可以接受参数来定制软件的编译方式，比如不为 GUI 环境加入任何额外支持——这对“无头”（headless，纯文本的远程服务器）来说才合理；或者牺牲速度换取最低内存占用——如果你的服务器内存很小，这可能才有意义。如果它向你提问，一律按默认回答——看到一些 WARNING 信息也不要慌，多半不会有事。
* `make` ——编译软件，通常会调用 GNU 编译器 `gcc`。这一步可能刷出大量吓人的文字，耗时一两分钟——而像 LibreOffice 这种特别大的软件包可能要一两个小时。
* `make install` ——这一步把编译好的文件连同文档安装进你的系统，某些情况下还会设置服务和计划任务等。在此之前你只是在主目录里操作，而这一步是装到系统里、对所有用户生效，因此需要 `root`（根用户）权限。正因如此，你实际要运行的是：`sudo make install`。如果它提问，按默认回答即可。

这最后一步有可能已经覆盖了你原有的 `nmap`，但更可能的是，这个新版本被安装到了另一个位置。

一般来说，_/bin_ 放操作系统的关键部分，_/usr/bin_ 放不那么核心的实用工具，_/usr/local/bin_ 放你自己手动安装的软件。当你输入一条命令时，系统会按 PATH 环境变量里给出的目录逐个搜索，并运行第一个匹配到的结果。所以，如果存在 _/bin/nmap_，运行的就是它而不是 _/usr/local/bin_ 里的那个——但如果你给出想要的那个版本的“完整路径”，比如 _/usr/local/bin/nmap_，运行的就是那个版本。

`locate` 命令能非常快地搜索文件，但因为这些文件是刚刚添加的，我们需要手动更新文件索引：

`sudo updatedb`

然后搜索这个索引：

`locate bin/nmap`

它应该能同时找到你的新旧两个 `nmap` 副本。

现在分别试着运行它们，比如：

`/usr/bin/nmap -V`

`/usr/local/bin/nmap -V`

`nmap` 这个工具不依赖任何其他软件包或库，所以从源码安装非常容易。大多数其他软件包都有很多“依赖”，即便有清楚的讲解，手动从源码安装它们也相当有挑战性（可以看看这个典型例子：<http://oss.oetiker.ch/smokeping/doc/smokeping_install.en.html>）。

**注意**：这一切都是在 `apt` 体系之外完成的，所以当你运行 `apt update` 时，这个二进制不会得到更新。对 `nmap` 这样的工具来说，这大概不算什么大事，但任何作为对外服务运行的东西，你必须明白：从现在起要自己跟踪该应用（及其全部依赖）的安全通告，并在修复版本发布后自行安装。对生产服务器来说，这是实实在在的麻烦和风险。

## 本课命令速查（中文版新增）

| 命令 | 用途 |
| --- | --- |
| `sudo apt install build-essential` | 安装编译器等构建工具链 |
| `nmap -V` | 查看已安装的 nmap 版本 |
| `which nmap` | 查看命令对应的可执行文件位置 |
| `cd` | 回到主目录 |
| `wget -v <URL>` | 下载文件并显示进度 |
| `ls -ltr` | 按时间排序列出目录（最新的在最后） |
| `tar -jxvf nmap-7.70.tar.bz2` | 一步解开 bz2 压缩的 tarball（`-j` 先解压、`-x` 解开、`-v` 显示、`-f` 指定文件名） |
| `./configure` / `make` / `sudo make install` | 源码安装三步：检查环境 / 编译 / 安装进系统 |
| `sudo updatedb` | 更新 `locate` 的文件索引 |
| `locate bin/nmap` | 按索引快速查找文件 |
| `/usr/bin/nmap -V` / `/usr/local/bin/nmap -V` | 分别运行发行版与源码版 |
