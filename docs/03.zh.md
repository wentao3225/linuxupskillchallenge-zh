## 引言

你可能一直是以普通用户身份登录服务器的，但你多半已经知道：[root（根用户）是 Linux 系统里的超级用户](https://www.ssh.com/academy/pam/root-user-account#what-is-a-root-user?)。这个管理用的“超级用户”账户权力无边——一条命令里手一抖，就可能让你的服务器瘫痪。系统管理员面对的通常都是既重要又远程的系统，所以避免这类错误是*天大的好事*。

远古时候，系统管理员习惯直接以 `root` 登录生产系统；如今公认的最佳实践是不鼓励乃至禁止直接用 `root` 登录，改为把权限授予指定的可信用户，让他们通过 `sudo` 命令去运行那些只有 root 才能执行的命令。

## 局部修改与全局修改

**全局（Global）**：任何用户都能使用的程序/环境，在整台系统上通用。全局修改影响所有用户。

**局部（Local）**或**按用户（By user）**：某个特定用户运行的程序/环境，其他用户用不到。局部修改只影响一个用户。

## 你是谁？你能做什么？

Linux 系统里有三类用户：

* `root`——威力强大的超级用户，可以在系统的任何层面执行任何命令。他既能做所有全局修改，也能替任何用户做局部修改。
* `sudoers`——被允许使用 `sudo` 的普通用户，也就是说，他们可以在系统的一个或多个层面执行命令，能做一部分或全部全局修改。常见的情况是至少有一个 sudoer 拥有与 root 同等的权力，而其他 sudoer 拥有的权限则可多可少。
* `regular users`（普通用户）——能使用系统，但只能做局部修改，也就是只能处理自己的文件/目录和环境变量。

关于用户及其权限的更多细节，我们会在[第 13 天](13.md)和[第 14 天](14.md)展开。

## 别再使用 root

如果你是用[大型 VPS（虚拟专用服务器）提供商](00-VPS-big.md)之一创建的虚拟机，`root` 已经被“禁用”，而你的默认用户（ubuntu、azureuser 之类）已经拥有 `sudo` 权力。

不过，如果你真的、*真的*想用 `root`，在 [AWS](https://tecadmin.net/how-to-enable-ssh-as-root-on-aws-ubuntu-instance/)、[Azure](https://stackoverflow.com/questions/24313562/root-login-ubuntu-vm-on-azure) 和 [GCP](https://cloud.google.com/compute/docs/connect/root-ssh) 上都有办法做到。**但请自担风险！**

反过来，如果你是[在本地](00-Local-Server.md)创建的虚拟机，或者用的是[其他 VPS 提供商](00-VPS-small.md)，那你的 `root` 用户多半是现成可用的。

别再用 root 了。如果你跟着前面的指南操作，此时应该已经创建了一个普通用户并把它加进了 sudoers 用户组，就像这样：

    adduser snori74
    usermod -a -G sudo snori74

把普通用户加进带 `sudo` 权限的用户组是最省事的做法，因为 `sudo` 用户组在 Ubuntu 里相当标准。当然，也可以用 `visudo` 命令修改 `/etc/sudoers` 来达到同样的目的。

从现在起，就用这个新用户登录。用 `whoami` 可以打印出你登录所用的用户名。

## 修改密码

如果你用密码登录（而不是公钥），现在正是确保密码足够强壮、独一无二的好时机——至少 10 个字母数字字符——因为你的服务器完全暴露在不断尝试闯入的机器人面前。如果你还在用 `root`，这一点尤其重要。

用 `passwd` 命令修改你的密码。

具体做法：想好一个安全的新密码，然后输入 `passwd`，按“Enter”，提示时给出当前密码，再给出你选定的新密码并确认——然后把它写到什么地方记下来。当然，在生产系统上，公钥和/或双因素认证才是更合适的选择。

## 关于“加固”的一点说明

你的服务器的安全保障来自两点：安全更新保持最新，以及你设置了*又长、又强、又独特*的密码——或者已经在用公钥。虽然它暴露在公网上、很可能正被持续攻击，但它应该是相当安全的。

下周我们会看看如何观察这些攻击，但现在只需明确一点：读读“SSH 加固”方面的资料没问题，不过像改默认端口、上 `fail2ban` 这类操作，在我们学习阶段既无必要也无帮助——没有它们你也安全得很。

## sudo 的威力

* 用下方“资源”小节里的链接弄明白 `sudo` 的工作原理
* 试试 `cat /etc/shadow`，你能查看这个文件的内容吗？
* 这个文件存放的是哈希过的密码，是入侵者的头号目标——他们想把它抢走，用离线密码破解工具把密码还原出来。所以完全可以认定：它不应该让系统里未获授权的用户看到。
* 现在加上 `sudo` 再试一次，即 `sudo cat /etc/shadow`
* 试试直接运行 `reboot` 命令，然后再通过 `sudo` 运行（即 `sudo reboot`）

重连回来之后：

* 用 `uptime` 命令确认服务器确实完整重启过了
* 用 `last` 命令按用户名（比如 `snori74`）过滤，查看登录历史。如果这是你第一次使用非 root 用户，应该只有一条记录（即 `last snori74`）
* 再对比一下你以 root 登录的记录：`last root`
* 更进一步，用 `sudo lastb` 查查针对 root 的**失败登录尝试**
* 用 `sudo -i` 命令试试彻底“变身 root”。如果你要以“root 身份”执行一串命令，这会很顺手。注意观察提示符的变化。
* 输入 `exit` 或 `logout`，回到你自己的普通“管理员”登录。
* 输入 `sudo journalctl -e /usr/bin/sudo`，看看最近几次 `sudo` 的使用记录

*一般来说，调用 `sudo` 命令时会要求你用密码再次确认身份。不过这一点可以在 sudoers 配置文件里改掉，让它不再提示输入密码。我们会在[第 13 天](13.md)详细讨论。*

## 管理任务

后面我们会细讲你能在服务器上做的许多事情，这里先给出几个需要 `sudo` 的简单管理任务作为示例。

如果你愿意，现在就可以给服务器改名。传统做法是编辑 `/etc/hostname` 和 `/etc/hosts` 两个文件然后重启——但更现代、也更受推荐的方式是用 `hostnamectl` 命令，像这样：

    sudo hostnamectl set-hostname mylittlecloudbox

不需要重启，但如果你想在提示符里看到新名字，用 `bash` 开一个新会话即可（或者登出再登录，效果相同）。

对于云服务器，你可能会发现重启之后主机名又变了回去。要避免这一点，编辑 `/etc/cloud/cloud.cfg`，把 “preserve_hostname” 那一行改成：

    preserve_hostname: true

你也可以考虑改一改服务器使用的时区。默认很可能是 UTC（即 GMT）——对遍布全球的服务器机群来说，这相当合适。你也可以把它设成服务器所在的时区，或者你（和你的总部）所在的时区。对公司来说，这不是能随口拍板的决定，但眼下你尽管随性改！

先用下面的命令查看当前设置：

    timedatectl

然后列出所有可用的时区：

    timedatectl list-timezones

最后选定一个，像这样：

    sudo timedatectl set-timezone Australia/Sydney

确认一下：

    timedatectl

这么改带来的主要实际影响有两处：(1) 计划任务的执行时间；(2) 保存在 `/var/log` 下的日志文件的时间戳。一旦改动，记录下来的日期和时间自然会出现一段“跳跃”。

## 能力越大，责任越大

作为 Linux 系统管理员，你可能要在一些自己没什么控制权的客户系统或定制系统上工作，其中很多系统默认以 `root` 做所有事。你得能在这类系统上安全工作——唯一的保护手段，就是在按 `Enter` 之前再三确认。

另一方面，在你完全掌控的系统上，建议给自己（以及任何共同管理的同事）建一个带 `sudo` 权限的“普通”账户。这在 Ubuntu 上是标配，在 Debian、CentOS、RHEL 等其他流行的服务器发行版上配置起来也不难。

即便如此，在做出全局修改之前采取必要的预防措施依然重要，以免一不小心把自己锁在门外或惹出其他乱子。用测试环境、检查语法错误和笔误、盯紧日志文件——这些实践终会成为你的第二天性。

### `sudo -i` 和 `sudo -s` 有什么区别？

`sudo -i` 和 `sudo -s` 都是让用户在基于 Unix 的系统上取得 root 权限的命令，但两者的工作方式有些差别。

* `sudo -i` 的 i 代表 “interactive”（交互式），它会为 root 用户启动一个新的登录 shell。也就是说，它会以 root 用户的家目录和 shell 配置文件为 root 创建一套全新环境，效果类似直接以 root 登录；在这个 shell 里执行的任何命令都拥有 root 的权限。
* `sudo -s` 的 s 代表 “shell”，它同样为 root 用户启动一个新 shell，但并不会创建新的登录 shell。也就是说，它不会改变当前用户的环境或 shell 配置文件。在这个 shell 里执行的命令同样拥有 root 权限，但环境仍是当前用户的那一套。

简单总结：`sudo -i` 更“彻底”，会创建一个带 root 完整环境的新 shell；`sudo -s` 则温和一些，只是启动一个拥有 root 权限、但沿用当前用户环境的新 shell。

## 本课命令速查（中文版新增）

| 命令 | 用途 |
| --- | --- |
| `passwd` | 修改当前用户密码 |
| `sudo <命令>` | 以 root 权限执行单条命令（如 `sudo cat /etc/shadow`） |
| `sudo -i` | 彻底“变身” root（新登录 shell，带 root 完整环境） |
| `sudo -s` | 以 root 权限开一个新 shell（沿用当前环境） |
| `whoami` | 打印当前登录的用户名 |
| `last <用户>` | 查看用户的登录历史 |
| `sudo lastb` | 查看失败的登录尝试 |
| `uptime` | 查看系统运行时长（确认重启成功） |
| `reboot` | 重启服务器（普通用户需 `sudo reboot`） |
| `sudo journalctl -e /usr/bin/sudo` | 查看最近几次 sudo 的使用记录 |
| `adduser <用户>` / `usermod -a -G sudo <用户>` | 创建普通用户并加入 sudo 用户组 |
| `visudo` | 修改 `/etc/sudoers` 配置 |
| `hostnamectl set-hostname <名字>` | 修改主机名 |
| `timedatectl` | 查看时间设置；`list-timezones` 列出可用时区、`set-timezone` 设置时区 |
| `exit` / `logout` | 退出当前会话 |
