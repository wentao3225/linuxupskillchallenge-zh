## 添加新用户

给你的新用户起个名字——示例里我们用 “helen”。添加这个新用户：

`sudo adduser helen`

（Linux 里名字区分大小写，所以 “Helen” 会是另一个完全不同的用户）

“adduser” 命令在各个发行版上细节略有差异——如果它没有提示你给新用户设置密码，现在就手动设一个：

`sudo passwd helen`

现在，用户的文本数据库 `/etc/passwd`（用 `less` 看看吧）里会多出一条记录，`/etc/group` 文件里会多出一个同名用户组。该用户的密码哈希则存放在 `/etc/shadow`（用 “sudo” 你也能读到它——顺便查查它的权限是怎么设的。出于显而易见的原因，它可不是谁都能读的）。

如果你用惯了其他操作系统，这可能难以置信：这几个简单的文本文件就是 Linux 用户数据库的全部——理论上你甚至可以直接编辑它们来创建用户和用户组，不过通常不建议这么干。

另外，`adduser` 还会创建一个家目录（home directory），比如 `/home/helen`，权限也都设得恰到好处。

**注意！** `useradd` 和 `adduser` 不是一回事。两者都能创建新用户，但用起来的交互差别很大。差异详情见“扩展”部分的链接。

## 添加新用户组

假设我们想让组织里的所有开发人员拥有自己的用户组，这样他们就能访问同一批东西。

`sudo groupadd developers`

大多数现代 Linux 系统都会为每个用户自动建一个同名用户组，比如用户 “ubuntu” 就是 “ubuntu” 用户组的成员。不过如果你愿意，也可以在创建新用户时用 `ingroup` 参数直接把他放进已有的用户组。比如新用户 `fred` 可以这样创建：

`sudo adduser --ingroup developers fred`

## 把用户加进用户组

一个用户可以同时属于多个用户组，用户组也可以按需增加。

想看你属于哪些用户组，输入：`groups`

在 Ubuntu 系统上，第一个创建的用户（对你来说就是 `ubuntu`）应该属于 `ubuntu`、`sudo` 和 `admin` 这几个用户组——试着列出 `/var/log` 目录：你能用 `less` 读到 `/var/log/auth.log` 的内容，正是因为你属于 `sudo` 用户组。

> **译注**：原文称第一个用户属于 `ubuntu`、`sudo` 和 `admin` 三个组，且能读 `/var/log/auth.log` 是因为 `sudo` 组成员身份。在现行 Ubuntu（如 22.04/24.04）上，第一个用户实际属于 `sudo`、`adm` 等用户组；`/var/log/auth.log` 的属组是 `adm`，能读它靠的是 `adm` 组成员身份；原文提到的 `admin` 是旧版 Ubuntu 的遗留用户组，如今默认没有成员。

“root”（根用户）可以用这条命令把用户加进已有的用户组：

`usermod -a -G group user`

所以你的 `ubuntu` 用户只要在命令前加上 `sudo`，也能做同样的事。

由于新用户 `helen` 不是系统里第一个创建的用户，她没有运行 `sudo` 的权限——而 _你的_ 用户有，靠的正是 `sudo` 组成员身份。

想看看 `helen` 都属于哪些用户组，可以像这样切换用户、“变成 helen”：

`sudo su helen`

然后：

`groups`

如果你想做只有 sudo 用户才能做的事——比如读 `/var/log/auth.log` 的内容——就算加上 `sudo` 前缀也没用。Helen 不是 sudo 用户，没有权限执行这个操作。

现在输入 “exit” 回到你自己的普通用户，然后用这条命令把 `helen` 加进 `sudo` 组：

`sudo usermod -a -G sudo helen`

不用再切换用户了，直接运行 `groups helen` 验证即可。对 `fred` 也照做一遍，看看一切是否如预期。

再看看你的这些新用户里，有没有谁能 `sudo reboot`。

## sudo 的巧妙用法

你的新用户只是个普通用户，还不能用 `sudo` 以提权后的身份运行命令——除非我们给他配置。我们固然可以直接把他加进一个预设好、能用 sudo 以 root 身份做 _任何事_ 的用户组（就像前面对 `helen` 做的那样）——但我们不想给 `fred` 这么大的权力。

用 `ls -l` 看看 `/etc/sudoers` 这个文件的权限。魔法就在这里定义，你会看到它被管得很严。不过你应该可以用 `sudo less /etc/sudoers` 查看它。你要在这里给你的新用户加一条新规则，而这需要用一个专门的工具：`visudo`

要运行它，可以先用这条命令临时“变成 root”：

`sudo -i`

注意你的提示符已经变成了 `#`。

现在直接运行 `visudo` 开始编辑 `/etc/sudoers`——通常会调用 `nano` 来编辑。

`/etc/sudoers` 里所有以 “#” 开头的行都是可选的注释。你要加上类似这样的几行：

	# Allow user "fred" to run "sudo reboot"
	# ...and don't prompt for a password
	#
	fred ALL = NOPASSWD:/sbin/reboot

这几行加在哪儿都行，看着合理即可。`visudo` 会自动检查语法，有错就不让你保存——因为 sudoers 文件一旦写坏，你可能把自己锁在服务器门外！

输入 `exit` 摘下魔法帽，变回你的普通用户——注意提示符也变回了 `$`。

## 测试

用你的测试用户登录，输入 `sudo reboot` 来验证。
另外，你可以这样“变成” helen：

`sudo su helen`

如果你的 ssh 配置只允许公钥登录，你还需要设置好 `/home/helen/.ssh/authorized_keys`——包括把属主和权限都弄对。就当是对这部分内容的一次小测验！

## 本课命令速查（中文版新增）

| 命令 | 用途 |
| --- | --- |
| `sudo adduser helen` | 创建新用户（自动创建家目录和同名用户组） |
| `sudo passwd helen` | 为用户设置 / 重置密码 |
| `sudo groupadd developers` | 创建新用户组 |
| `sudo adduser --ingroup developers fred` | 创建用户并直接加入指定用户组 |
| `groups` / `groups helen` | 查看自己 / 指定用户所属的用户组 |
| `usermod -a -G group user` | 把用户追加进用户组（配合 `sudo` 使用） |
| `sudo su helen` | 切换（“变成”）另一个用户 |
| `sudo -i` | 临时变为 root，提示符变 `#` |
| `visudo` | 安全地编辑 `/etc/sudoers`（自动检查语法） |
| `sudo reboot` | 重启服务器（按 sudoers 中的授权生效） |
