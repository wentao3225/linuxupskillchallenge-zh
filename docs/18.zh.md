## 引言

管理远程服务器时，日志是你最好的朋友，而磁盘空间问题可能是你最坏的敌人——所以尽管 Linux 应用普遍非常“擅长”生成日志，还是得有人管住它们。

`logrotate` 这个应用就是用来管住日志的。借助它，你可以定义保留多少天的日志；把日志切成便于管理的小文件；压缩它们以节省空间，甚至干脆把它们放到另一台完全独立的服务器上。

好的系统管理员热爱自动化——让计算机自动去干那些枯燥重复的活，天经地义。

## 你的日志在轮转吗？

看看你的日志目录——_/var/log_，以及 _/var/log/apache2_ 这类子目录。你能看出日志其实已经在轮转了吗？你应该能看到一个 _/var/log/syslog_ 文件，同时还有一系列更早的压缩版本，文件名类似 _/var/log/syslog.1.gz_。

## 它们什么时候轮转？

你应该还记得，`cron` 通常被设置为运行 _/etc/cron.daily_ 里的脚本——进去看看，应该能看到一个叫 `logrotate` 的脚本——也可能叫 _00logrotate_，靠这个名字排到最前，确保它是当天第一个运行的任务。

## 配置 logrotate

总体配置写在 _/etc/logrotate.conf_ 里——先看看它，再看看 _/etc/logrotate.d_ 目录下的那些文件，它们的内容会合并进来，构成完整的配置。你很可能会看到一个叫 _apache2_ 的文件，内容类似这样：

     /var/log/apache2/*.log {
     weekly
     missingok
     rotate 52
     compress
     delaycompress
     notifempty
     create 640 root adm
     }

这里面大部分相当直白：所有 apache2 的 .log 文件每周轮转一次，保留 52 份压缩副本。

通常你安装一个应用时，会顺手得到一份合适的 logrotate“配方”，所以一般不需要从零写起。不过，默认设置未必符合你的需求，作为系统管理员，你完全可以编辑它们——比如上面默认的 _apache2_ 配方是保留 52 份周志，但你可能觉得每天轮转、把一份副本自动邮件发给审计员、服务器上只保留 30 天的日志，这样对你更有用。

## 本课命令速查（中文版新增）

| 命令 | 用途 |
| --- | --- |
| `ls /var/log` | 查看日志目录，确认 `syslog`、`syslog.1.gz` 等轮转产物 |
| `ls /etc/cron.daily` | 查看 `cron` 每天运行的任务，其中应有 `logrotate` |
| `cat /etc/logrotate.conf` | 查看总体轮转配置 |
| `ls /etc/logrotate.d` / `cat /etc/logrotate.d/apache2` | 查看各应用的轮转“配方”（`weekly`、`rotate 52`、`compress` 等） |
| `sudo nano /etc/logrotate.d/apache2` | 把 `weekly` 改成 `daily` 等按需调整 |
