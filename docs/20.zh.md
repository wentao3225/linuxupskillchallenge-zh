## 引言

今天是课程的最后一课。如果你一路坚持学完了所有课程，好好拍拍自己的背鼓励一下！

你应该已经体会到，系统管理员始终强调的一件事就是尽可能自动化；你也见识了 Linux 系统有多“透明”——前提是你知道去哪儿看！

在这最后一课上，我们要讲讲如何编写小程序——也就是“shell 脚本”——来帮你管理系统。

在 Linux 命令行上输入命令时，你其实是在和“命令解释器”（command interpreter）直接对话，它也叫“shell”。这个 shell 通常是 _bash_，所以当你把一组命令串起来做成脚本时，成果既可以叫“shell 脚本”（shell script），也可以叫“bash 脚本”（bash script）。

为什么要写脚本，而不是每次手动敲命令？

* 省打字。还记得我们用一长串 `grep`、`cut` 和 `sort` 命令翻查日志吗？这种事要做上好几次的话，把它写成脚本就能省下打字——也省下打错字！
* 参数。同一个脚本可以根据你传入的参数做不同的事。
* 自动化。把脚本放进 _/etc/cron.daily_，它就会每天运行；或者在相应的 _/etc/rc.d_ 文件夹里放一个指向它的符号链接，就能让它在系统每次关机或开机时运行。

## 今日任务

* 写一个简短的脚本，列出尝试登录你服务器次数最多的前 3 个 IP 地址

## 从 shebang 开始！

脚本不过是普通的文本文件，但只要你给它们设置了“可执行”权限，系统就会在文件开头寻找一个以 “#” 和 “!” 这两个字符开头的特殊行——它被称为 “shebang”（或 “crunchbang”）。

这一行通常长这样：

     #!/bin/bash

一般来说，以 “#” 开头的内容都会被当作注释，但如果它出现在第一行、并且后面跟着 “!”，就会被解释为：_“请把余下内容交给 /bin/bash 这个程序，让它当作脚本来执行”_。我们的所有脚本都会用 _bash_ 语言编写——也就是你在这门课程里一直在命令行上敲的那套东西——不过脚本也可以用许多其他“脚本语言”来写：Perl 写的脚本可能以 `#!/usr/bin/perl` 开头，Python 的则以 `#!/usr/bin/env python3` 开头。

## 你的第一个脚本

我们将利用 _/var/log/auth.log_ 里的条目，写一个小脚本，列出最近一次尝试登录你服务器而失败的来源。

用 `vim` 在你的主目录下创建一个名为 `attacker` 的文件，内容如下：

     #!/bin/bash
     #
     #   attacker - prints out the last failed login attempt
     #
     echo "The last failed login attempt came from IP address:"
     grep -i "disconnected from" /var/log/auth.log|tail -1| cut -d: -f4| cut -f7 -d" "

像这样在脚本开头写注释并非严格必要（计算机会忽略它们），但这是一个值得养成的职业好习惯。

把它变成可执行文件：

`chmod +x attacker`

现在要运行这个脚本，只需按名字调用它——但当前目录（出于慎重考虑）并不在你的 $PATH 里，所以你得用下面两种方式之一：

     /home/support/attacker
     ./attacker

一旦你对某个脚本满意、希望它能随手可用，通常就该把它挪到 $PATH 上的某个位置——_/usr/local/bin_ 一般是合适的去处。试试这样：

`sudo mv attacker /usr/local/bin/attacker`

……从此以后，只要你输入 `attacker`，它就能直接运行。

## 扩展这个脚本

你可以把这个脚本扩展一下，让它要求一个参数，并且在你不给参数时打印一些用法帮助。这里有几个新技巧，值得仔细研究：

```
#!/usr/bin/env bash
#
#   topattack - list the most persistent attackers
#
# Ensure "graceful exit" in case the script was sourced.
if [[ ${BASH_SOURCE[0]} != "$0" ]]; then
        echo "Don't source this file. Execute it.";
        return 1;
fi;
# Display usage hint if the script was executed with no/invalid argument.
if [[ -z "$1" ]] || [[ ! "$1" =~ ^[0-9]+$ ]] || (( $1 < 1 )); then
        echo -e "\nUsage:\n\t$(basename "${BASH_SOURCE:-$0}") <NUM>";
        echo "Lists the top <NUM> attackers by their IP address.";
        echo -e "(<NUM> can only be a natural number)\n";
        exit 0;
fi;
# Make sure the log file is available for parsing by this user.
if [[ ! -f "/var/log/auth.log" ]] || [[ ! -r "/var/log/auth.log" ]]; then
        echo -e "\nI could not read the log file: '/var/log/auth.log'\n";
        exit 2;
fi;
# Use 'cat' command and "here document" to avoid repeated 'echo' commands.
cat << _EndOfHeader_

Top $1 persistent recent attackers

Attempts      IP
-----------------------
_EndOfHeader_
# Too long command pipelines can be spanned over multiple lines with \
# followed immediately by a newline character (i.e. ENTER, RETURN, '\n')
grep 'Disconnected from authenticating user root' "/var/log/auth.log" \
 | cut -d':' -f 4 | cut -d' ' -f 7 | sort | uniq -c | sort -nr | head -n "$1";
```

同样，用 `vim` 创建 `"topattack"`，用 `chmod` 赋予可执行权限，等它工作正常后再用 `mv` 移到 _/usr/local/bin_。

（顺便一提：你可以用 `whois` 查询这些 IP 的详情——但请注意，那些正在“攻击”你的机器，可能只是一台被黑客攻陷的无辜机器。）

像这样的一组简单脚本，你完全可以轻松攒出来，让你的系统管理工作更简单、更快、更少出错。

如果自动化、脚本化你的日常事务正是你喜欢做的事，你或许还想把机器和服务的部署也脚本化。虽然你可以像本课展示的那样用 bash 脚本来做，但选择 ansible、cloudinit 或 terraform 这类编排框架也有一些好处。这些框架超出了本课程的范围，但值得一读。

## 本课命令速查（中文版新增）

| 命令 | 用途 |
| --- | --- |
| `#!/bin/bash` | shebang 行：告诉系统用 bash 执行本脚本 |
| `chmod +x attacker` | 给脚本加可执行权限 |
| `./attacker` | 运行当前目录下的脚本（当前目录不在 $PATH 中） |
| `sudo mv attacker /usr/local/bin/attacker` | 移入 $PATH 目录，之后直接输入 `attacker` 即可运行 |
| `grep` / `cut` / `sort` / `uniq -c` / `head` | 在 `attacker` 与 `topattack` 中组合使用，从 `/var/log/auth.log` 统计失败登录来源 |
| `whois <IP>` | 查询 IP 归属详情 |
