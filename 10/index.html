    第 10 天 - 计划任务

    • 教学视频：Lesson video（英文）
    • 补充视频：Timers and scheduling（英文）

    引言

    Linux 有一整套丰富的功能用来运行计划任务。优秀系统管理员的一个关键特质，就是让计算机替你干活（有时被歪曲成“懒惰”！）——而一套配置良好的计划任务，正是让服务器长期保持良好运转的关键。

    基于时间的任务调度器 cron(8) 是 Linux 系统管理员最常用的一个。自 Unix System V 时代起，它就以与现在大致相同的形态存在至今，使用的是一套广泛通行的标准化语法。

    使用 at 调度一次性任务

    如果你在用 Ubuntu，很可能需要先安装 at 软件包。

    sudo apt update
sudo apt install at

    我们将用 at 命令来调度一个一次性任务，让它 at（在）未来的某个时刻运行。

    接下来，先打印连接到标准输入的终端设备文件名（在 Linux 里一切皆文件，你的终端也不例外！）。我们打算在未来的某个时刻向终端输出一点内容，借此体会用 at 调度未来任务是什么感觉。

    vagrant@ubuntu2204:~$ tty
/dev/pts/0

    现在调度一条命令，让它在 1 分钟后向终端输出一句问候。

    vagrant@ubuntu2204:~$ echo 'echo "Greetings $USER!" > /dev/pts/0' | at now + 1 minutes
warning: commands will be executed using /bin/sh
job 2 at Sun May 26 06:30:00 2024

    片刻之后，终端上应该就会打印出这句问候。

    ...
vagrant@ubuntu2204:~$ Greetings vagrant!

    实际中并不常用 at 来调度一次性任务，但万一哪天需要，你现在也知道大致怎么做了。下一节我们将学习用 cron 和 crontab 调度基于时间的任务。

    想更深入地了解用 at 调度任务，请参阅下方延伸阅读一节中的相关文章。

    使用 crontab 调度任务

    在 Linux 中，我们用 crontab 命令与 cron 守护进程调度的任务打交道。每个用户——包括 root（根用户）——都可以安排以自己身份运行的任务。

    用 crontab -l 显示你当前用户的 crontab。

    vagrant@ubuntu2204:~$ crontab -l
no crontab for vagrant

    除非你早已为自己的用户创建过 crontab，否则此时多半还没有。我们来创建一个简单的 cronjob（cron 任务），看看它如何工作。

    用 crontab -e 命令来创建我们的第一个 cronjob。在 Ubuntu 上，如果这是你第一次编辑 crontab，会先弹出一个菜单，让你挑选顺手的编辑器。

    vagrant@ubuntu2204:~$ crontab -e
no crontab for vagrant - using an empty one

Select an editor.  To change later, run 'select-editor'.
  1. /bin/nano        <---- easiest
  2. /usr/bin/vim.basic
  3. /usr/bin/vim.tiny
  4. /bin/ed

Choose 1-4 [1]: 2

    选好你喜欢的编辑器，然后按 Enter。

    在文件末尾添加下面这个 cronjob，然后保存并退出。

    * * * * * echo "Hello world!" > /dev/pts/0

    注意：请确保 /dev/pts/0 这个文件路径与前面 tty 命令打印出来的路径一致。

    接着再运行一次 crontab -l，看看刚刚装入的 crontab。你应当能在终端上看到自己创建的 cronjob。

    vagrant@ubuntu2204:~$ crontab -l
* * * * * echo "Hello world!" > /dev/pts/0

    这个 cronjob 会每分钟向你的终端打印一次字符串 Hello world!，直到我们删除或修改它。等上几分钟，看看它的效果。

    vagrant@ubuntu2204:~$ Hello world!
Hello world!
Hello world!
...

    等你玩够了，用 crontab -r 卸载掉刚创建的 crontab。

    理解 crontab 语法

    crontab 的基本语法如下：

    * * * * * command to be executed
- - - - -
| | | | |
| | | | ----- Day of week (0 - 7) (Sunday=0 or 7)
| | | ------- Month (1 - 12)
| | --------- Day of month (1 - 31)
| ----------- Hour (0 - 23)
------------- Minute (0 - 59)
    • 分钟的取值范围是 0 到 59。
    • 小时的取值范围是 0 到 23。
    • 日（月中第几天）的取值范围是 1 到 31。
    • 月份的取值范围是 1 到 12。
    • 星期的取值范围是 0 到 6，0 表示周日。

    译注：上图中星期字段的标注为 0–7（0 和 7 都表示周日），而下面一条写的是 0–6。两种说法都对——0 与 7 等价——只是原文前后表述不一致。

    每个字段都有一些运算符，可以作为一次指定多个值的简写方式：

    符号 含义
    * 通配符，表示该字段所有可能的取值
    , 用逗号分隔，列出多个值
    - 用连字符指定一个数值范围
    / 用斜杠指定周期 / 频率

    还有一个检查 cron 时间表达式的好帮手网站：crontab.guru。

    可以在 crontab.guru 上摆弄各种表达式，体会它们如何工作，也可以点击 random 按钮随机生成一个。

    今日任务

    1. 安排每日备份各个用户的主目录
    2. 安排一个任务，找出超过 7 天的备份并删除它们

    自动化常见的系统管理任务

    cronjob 的一个常见用途，就是给各种东西安排备份。下面我们以 root 用户身份创建一个 cronjob，用 tar 工具把所有用户的主目录打包成一个压缩归档。tar 是 “tape archive”（磁带归档）的缩写，这个名字可以追溯到 Unix 与 Linux 的早期岁月——那时数据经常归档到类似盒式磁带的磁带存储介质上。

    一般来说，最好先把命令或脚本手动测试一遍，再安装成 cronjob。我们先手动运行一版 tar 命令，给 /home 创建一个备份。

    vagrant@ubuntu2204:~$ sudo tar -czvf /var/backups/home.tar.gz /home/
tar: Removing leading `/' from member names
/home/
/home/ubuntu/
/home/ubuntu/.profile
/home/ubuntu/.bash_logout
/home/ubuntu/.bashrc
/home/ubuntu/.ssh/
/home/ubuntu/.ssh/authorized_keys
...

    注意：我们给 tar 传了 -v（verbose，详细输出）参数，以便看清它在做什么。-czf 依次代表 “create”（创建）、“gzip compress”（gzip 压缩）和 “file”（文件）。更多信息见 man tar。

    我们再用 date 命令把备份日期插进文件名。既然是每日备份，这个 cronjob 跑上几天之后，我们就会得到好几份备份，每个归档都_打上_了对应日期的标签。

    vagrant@ubuntu2204:~$ date
Sun May 26 04:12:13 UTC 2024

    date 命令默认打印的字符串不太好用。我们改用 ISO 8601 格式输出日期——有时也称为“ISO 日期”。

    vagrant@ubuntu2204:~$ date -I
2024-05-26

    这个字符串实用多了，把它与 tar 命令结合，就能创建文件名里带今天日期的归档。

    vagrant@ubuntu2204:~$ sudo tar -czvf /var/backups/home.$(date -I).tar.gz /home/
tar: Removing leading `/' from member names
/home/
/home/ubuntu/
...

    看看我们创建的这些备份，理解日期是如何被插进文件名的。

    vagrant@ubuntu2204:~$ ls -l /var/backups
total 16
-rw-r--r-- 1 root root 8205 May 26 04:16 home.2024-05-26.tar.gz
-rw-r--r-- 1 root root 3873 May 26 04:07 home.tar.gz

    注意：系统管理员常把这类 .tar.gz 文件叫作 tarball。

    用 sudo crontab -e 创建并编辑 root 的 crontab，加入下面这个 cronjob。

    0 5 * * * tar -zcf /var/backups/home.$(date -I).tar.gz /home/

    这个 cronjob 每天凌晨 05:00 运行。几天之后，/var/backups 里就会积下好几份用户主目录的备份。

    如果放任这个 cronjob 一直跑下去，过上一阵子，/var/backups 里就会堆满备份。磁盘占用会随之增长，甚至可能把磁盘塞满。最好别让这种事发生。为了化解这一风险，我们再设置一个每天运行的 cronjob，清理不再需要保留的旧备份。

    find 命令就像一把瑞士军刀：可以按各种条件查找文件，把它们列出来或者做其他处理——比如删除。我们要打造一条 find 命令，找出我们创建的所有备份，并删掉其中超过 7 天的。

    先找出所有备份并列出来，感受一下 find 命令是怎么工作的。

    vagrant@ubuntu2204:~$ sudo find /var/backups -name "home.*.tar.gz"
/var/backups/home.2024-05-26.tar.gz
...

    这条命令做的是：在 /var/backups 里查找所有以 home. 开头、以 .tar.gz 结尾的文件。* 是通配符，能匹配任意字符串。

    就我们的情形而言，需要创建一个计划任务，找出 /var/backups 里所有超过 7 天的文件并删除。运行 sudo crontab -e，装入下面这个 cronjob。

    30 5 * * * find /var/backups -name "home.*.tar.gz" -mtime +7 -delete

    注意：-mtime 是 “modified time”（修改时间）的缩写；这里 find 查找的是_修改_时间在 7 天之前的文件，+7 表示的就是这个含义。find 命令将在第 11 天 - 查找文件……中更详细地介绍。

    到这里，我们的 crontab 应该差不多是下面这个样子：

    vagrant@ubuntu2204:~$ sudo crontab -l
# Daily user dirs backup
0 5 * * * tar -zcf /var/backups/home.$(date -I).tar.gz /home/
# Retain 7 days of homedir backups
30 5 * * * find /var/backups -name "home.*.tar.gz" -mtime +7 -delete

    用 find ... -delete 这种写法来设置 cronjob，是系统管理员管理文件、清除不再需要的旧文件以防磁盘被塞满的惯用手法。更复杂的 _cron 脚本_也不罕见：把 tar、find、rsync 之类的工具组合起来，增量地或按计划管理备份，并根据真实场景实现更精细的保留策略。

    系统级 crontab

    还有一个系统级的 crontab，定义在 /etc/crontab 里。我们来看看这个文件。

    vagrant@ubuntu2204:~$ cat /etc/crontab
# /etc/crontab: system-wide crontab
# Unlike any other crontab you don't have to run the `crontab'
# command to install the new version when you edit this file
# and files in /etc/cron.d. These files also have username fields,
# that none of the other crontabs do.

SHELL=/bin/sh
# You can also override PATH, but by default, newer versions inherit it from the environment
#PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin

# Example of job definition:
# .---------------- minute (0 - 59)
# |  .------------- hour (0 - 23)
# |  |  .---------- day of month (1 - 31)
# |  |  |  .------- month (1 - 12) OR jan,feb,mar,apr ...
# |  |  |  |  .---- day of week (0 - 6) (Sunday=0 or 7) OR sun,mon,tue,wed,thu,fri,sat
# |  |  |  |  |
# *  *  *  *  * user-name command to be executed
17  *  *  *  *  root      cd / && run-parts --report /etc/cron.hourly
25  6  *  *  *  root      test -x /usr/sbin/anacron || ( cd / && run-parts --report /etc/cron.daily )
47  6  *  *  7  root      test -x /usr/sbin/anacron || ( cd / && run-parts --report /etc/cron.weekly )
52  6  1  *  *  root      test -x /usr/sbin/anacron || ( cd / && run-parts --report /etc/cron.monthly )

    基本语法此刻你已经熟悉了，不过你会注意到多出了一个字段 user-name（用户名）。它指定由哪个用户来运行任务，这是 /etc/crontab 这个系统 crontab 独有的。

    如今系统管理员已很少直接使用 /etc/crontab，而是鼓励各个用户（包括 root 用户）为自己的用户安装专属 crontab。用户 crontab 都存放在 /var/spool/cron 下，具体子目录因发行版而异。

    vagrant@ubuntu2204:~$ sudo ls -l /var/spool/cron/crontabs
total 8
-rw------- 1 root    crontab  392 May 26 04:45 root
-rw------- 1 vagrant crontab 1108 May 26 05:45 vagrant

    每个用户都有自己的 crontab，文件名就是用户名。

    注意，上面展示的系统 crontab 还管理着以_每日_、每周、_每月_方式运行、放在 /etc/cron.* 目录里的 cronjob。来看一个例子。

    vagrant@ubuntu2204:~$ ls -l /etc/cron.daily
total 20
-rwxr-xr-x 1 root root  376 Nov 11  2019 apport
-rwxr-xr-x 1 root root 1478 Apr  8  2022 apt-compat
-rwxr-xr-x 1 root root  123 Dec  5  2021 dpkg
-rwxr-xr-x 1 root root  377 Jan 24  2022 logrotate
-rwxr-xr-x 1 root root 1330 Mar 17  2022 man-db

    这些文件每一个都是执行某项例行任务的脚本，或者是指向脚本的快捷方式，由 run-parts 按文件名的字母顺序依次运行。所以在上例中 apport 会最先运行。用 less 或 cat 查看你系统里的几个脚本——很多看起来相当复杂，最好原样放着别动，但也有一些只是几行简单的命令。

    vagrant@ubuntu2204:~$ cat /etc/cron.daily/dpkg
#!/bin/sh

# Skip if systemd is running.
if [ -d /run/systemd/system ]; then
  exit 0
fi

/usr/libexec/dpkg/dpkg-db-backup

    除了用 crontab 调度任务，你也可以创建一个脚本，放进 /etc/cron.{daily,weekly,monthly} 中的某个目录，它就会按相应的周期自动运行。

    关于 systemd 定时器

    如今所有主流 Linux 发行版都带有 “systemd”。除了启动和停止服务，它_还_能通过“定时器”（timer）在特定时间运行任务。用下面的命令看看你的服务器上已经配置了哪些定时器：

    systemctl list-timers

    通过延伸阅读一节中的链接，进一步了解这些定时器的工作原理。

    命令 用途
    tty 显示当前终端对应的设备文件名
    at now + 1 minutes 调度一次性任务（把要执行的命令通过管道交给 at）
    crontab -l / crontab -e / crontab -r 查看 / 编辑 / 删除当前用户的 crontab
    sudo crontab -e / sudo crontab -l 编辑 / 查看 root 的 crontab
    tar -czvf 目标归档 源目录 创建 gzip 压缩归档并显示过程
    date -I 以 ISO 8601 格式输出当天日期
    find /var/backups -name "home.*.tar.gz" -mtime +7 -delete 查找并删除超过 7 天的匹配文件
    ls -l /etc/cron.daily 查看每日周期任务脚本
    systemctl list-timers 列出已配置的 systemd 定时器
