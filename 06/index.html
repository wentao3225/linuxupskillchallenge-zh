    引言

    简单的文本文件是 Linux 的核心，因此编辑它们是系统管理员的一项关键技能。面向初学者的简易文本编辑器有一大把，最常见的是 nano 和 pico。它们看起来像是上世纪 80 年代为 DOS 写的程序——不过还挺好上手，“摸索几下就会用”。

    然而，真正的系统管理员tm用的可是 vi——这个永远默认安装的编辑器——今天你就来上手它。

    Bill Joy 在上世纪 70 年代中期写出了 Vi——连我们将要重点学习的“现代版” Vim 也已经有 20 多年历史了。尽管岁数不小，它们至今仍是命令行服务器上的标配编辑器。此外，它们在程序员、甚至一些作家中间拥有一批忠实拥趸。Vim 其实是 Vi IMproved 的缩写，是 Vi 的直系后代。

    很多时候，你输入 vi，系统实际启动的却是 vim。想知道你的系统是否也如此，运行：

    vi --version

    如果 vi 命令实际上是一个指向 vim 的符号链接（symlink），你应该会看到类似下面的输出：

    user@testbox:~$ vi --version
VIM - Vi IMproved 8.2 (2019 Dec 12, compiled Oct 01 2021 01:51:08)
Included patches: 1-2434
Extra patches: 8.2.3402, 8.2.3403, 8.2.3409, 8.2.3428
Modified by team+vim@tracker.debian.org
Compiled by team+vim@tracker.debian.org

    没装 vim 怎么办？

    本课余下内容假定你的系统里已经装好了 vim——通常它默认就在。但有些情况下并没有，这时如果你运行下面的 vim 命令，可能会看到类似这样的报错：

    user@testbox:~$ vim
-bash: vim: command not found

    译注：英文原文中有两处链接（#option-1---alias-vim、#option-2---install-vim）原本指向不存在的锚点。本仓库已为英文版对应的两个小节标题用 attr_list 补上显式锚点，中文版沿用相同的锚点 id，链接现在可以正常跳转。

    方案一：给 vim 建别名

    一种办法是：把下面操作步骤里的 vim 命令统统换成 vi。Vim 向下兼容 Vi，下面的所有练习用 Vi 跑和用 Vim 跑应该效果一致。为了省事，我们也可以直接给 vim 命令建一个 别名（alias），让 vi 顶替它运行：

    echo "alias vim='vi'" >> ~/.bashrc
source ~/.bashrc

    方案二：安装 vim

    另一种办法——很多系统管理员多半会选的——是把 Vim 装上（如果还没装的话）。

    在 Ubuntu 上用系统软件包管理器安装 Vim，运行：

    sudo apt install vim

    **注意：**由于 Ubuntu Server LTS 是 Linux Upskill Challenge 推荐使用的 Linux 发行版，为其他各种 Linux “发行版”安装 Vim 就不在本课的讨论范围内了。不过，上面这条命令对大多数 Debian 系的 Linux “应该”都管用，所以如果你用的是 Mint、Debian、Pop!_OS 或其他各种 Ubuntu 衍生版，不妨试一试。至于 Debian 系之外的发行版，简单搜索几下，多半就能找到用它们的软件包管理器安装 Vim 的方法。

    你必须知道的两件事

    • 它有两种“模式”，行为差别极大
    • 屏幕上几乎没有任何提示，告诉你当前处于哪个模式！

    这两种模式是“普通模式”（normal mode）和“插入模式”（insert mode）。作为新手，只需记住：

    “按 Esc 两次或更多次，回到普通模式”

    “普通模式”用来输入命令，“插入模式”用来写文字——后者和普通文本编辑器的默认行为类似。

    操作步骤

    那么，先弄一个文本文档来练手。复制一份 /etc/services 就很合适：

    cd
pwd
cp -v /etc/services testfile
vim testfile

    此时文件已经显示在屏幕上，我们正处于“普通模式”。但和 nano 不同，屏幕上没有任何菜单，一切到底是怎么运作的，完全看不出个所以然！

    先按一两次 Esc 确保我们在普通模式（记得上面说的小技巧），然后输入 :q! 再按 Enter。这会在不保存任何修改的情况下退出——当你还不知道自己在干什么时，这是一项 至关重要 的第一技能！

    现在再进去随便玩玩，感受一下 vim 有多强大、多危险——然后再一次不保存退出：

    vim testfile

    用 h j k l 四个键移动光标（这是传统的 vi 操作方式），然后再试试方向键——如果方向键能用，尽管用——但请记住 hjkl 这几个键，因为说不定哪天你会碰到一台只有传统 vi 的系统，方向键在那里可不管用。

    接着随便上下翻翻这个文件，然后按前面讲的 Esc Esc :q! 退出。

    掌握了这些，我们来点进阶的。

    vim testfile

    这次，先往下移几行，然后按 3、再按一次 3、接着按 d、再按一次 d——眨眼间，文件里的 33 行内容就被删掉了！

    为什么？因为你正处于普通模式，33dd 是一条“删除 33 行”的命令。好，你还停在普通模式，再按 u——刚才的修改就被魔法般地撤销了。妙吧？

    现在你已经知道 vim 新手必备的三个基本招数了：

    • Esc Esc 永远能让你回到“普通模式”
    • 在普通模式下，:q! 永远能不保存任何改动直接退出
    • 在普通模式下，u 能撤销上一次操作

    下面来干点真正有用、有产出的事：

    • 查找内容：在普通模式下输入 G 跳到文件底部，输入 gg 跳回顶部。我们来搜索 “sun” 这个词：输入 /sun 找到第一处，按回车，然后反复按 n，逐个跳到后面的匹配位置。回到文件顶部（记得用 gg），再试试搜索 “Apple” 或 “Microsoft”。
    • 剪切与粘贴：回到文件顶部（用 gg），看看开头几行注释（以 “#” 作为第一个字符的那些行）。试着把它们剪掉再贴回来。操作很简单：把光标停在某一行上，然后（比如）输入 11dd 删除 11 行，紧接着按 P 把它们原样贴回——再往下挪一段，又按一次 P，把这 11 行再贴到那里。
    • 插入文本：把光标移到文件任意位置，按 i 进入“插入模式”（屏幕底部可能会显示出来），然后开始输入——写完后 Esc Esc 回到普通模式。
    • 把修改写入磁盘：在普通模式下输入 :w，即“写入”但留在 vim 里；或输入 :wq，即“写入并退出”。

    关于 vim，你 必须 学的就是这些了——不过只要你有时间， 可以 学的还有海量内容。下一步应该运行 vimtutor，把“官方” Vim 教程过一遍。第一次通常要花 30 分钟左右。想巩固 Vim 技能，就养成习惯，连续 1-2 周每天过一遍 vimtutor，你就能在基础操作上打下扎实的底子。

    **注意：**如果你在上面的练习里用的是vim 到 vi 的别名，那么现在也许正是个好时机去安装 vim——因为 vimtutor 命令正是随 Vim 一起提供的。装好 Vim 之后，你也可以在 Vim 内部运行 :help vimtutor 查看这份帮助，以及其他一些小技巧。

    不过，如果你真心想成为系统管理员，那么从现在起就要 下定决心，用 vim（或 vi）来完成你的所有编辑工作。

    最后提一句：你可能会看到关于 Vi 与 Emacs 之争的说法。那是程序员之间旷日持久的论战，与系统管理员无关——你需要学的是 vi/vim。

    为什么不能一直用 nano？

    • 作为专业人员，很多情况下你是在别人的系统上干活，而他们对稳定性往往极度敏感。你可能没有权限随手“sudo apt install ”——哪怕技术上完全可行。

    • 而 vi 在任何 Unix 或 Linux 机器上都是必备的——从微型 IoT 设备到超级计算机集群。事实上，Single Unix Specification 和 POSIX 都要求提供它。

    • 而且坦白说，它还是 Linux 老手们的一块试金石（shibboleth）。作为新人在面试里说自己“对 vi/vim 还只是个初学者”没问题——但要是说你讨厌它、而且总也记不住怎么退出，那可就悬了。

    总之，如果你打算以 Linux 为业，学会它很有必要；但如果只是在自家系统上折腾，那就尽管用 nano、pico 之类好了。
